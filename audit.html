FretLab Build Audit

Every feature family graded against what actually runs. The design layer is genuinely strong — the product layer underneath it is a demo. Here is the gap, feature by feature, and what closing it costs.

The one-line verdict

FretLab is a high-fidelity interactive prototype of a guitar SaaS, not yet a guitar SaaS.

The visual system is well above average — a real token set, a hand-built SVG fretboard, chord diagrams, a circle of fifths, a contribution graph, ten written theory lessons with working quizzes. That is more craft than most side projects ever reach.

But three structural facts define everything else in this report: the app makes no sound (zero AudioContext, zero getUserMedia), the app remembers nothing (zero localStorage, zero network calls — every number resets on refresh, and some are literally Math.random()), and the app has no mobile layout (zero @media queries across 10,390 lines).

For a practice tool, those three are not polish items. Sound is the product. Memory is the product. A guitarist practices with a phone on a stand. Everything else in this audit is secondary to those.

Read the grades this way.

Working means a user gets real value from it today. Shell means the UI is finished and the logic behind it is faked or absent. Stub means it is visible in the interface and does nothing at all when clicked.

Defects, in priority order

Ten concrete problems found by reading the source and validating its music data programmatically.

01

Eight chord voicings produce the wrong notes

I validated every entry in CHORD_LIBRARY by sounding its frets array against standard tuning and comparing to its declared notes. Eight disagree — and since ChordDiagram renders from frets, the diagram a learner copies is the wrong shape.

Chordfrets in fileWhat it should soundWhat it actually sounds
D-1,-1,2,3,2,-1D F♯ AA B F
Dm-1,-1,0,2,3,1D F AC E F G
C70,1,3,2,3,-1C E G B♭C E B♭ (no 5th)
E70,2,0,1,2,0E G♯ B DE G B C♯ D♯
Em70,0,0,2,2,0E G B DE G B (it’s Em)
Bdim-1,-1,0,1,0,1B D FA D♯ F G
Dsus4-1,-1,0,2,3,-1D G AC E G
Caug-1,-1,2,1,1,0C E G♯A A♯ D♯ E

The pattern in D, Dm and Dsus4 is a two-position array shift — someone typed the familiar low-to-high shape into a high-to-low array. Em7 and C7 are simply missing their 7th and 5th.

Fix: correct the eight arrays, then add a build-time assertion that derives notes from frets and fails the build on mismatch. Never hand-maintain both sides of that pair again — derive notes from frets at runtime and delete the field.

02

Nothing in the app makes a sound

There is no AudioContext, no <audio>, no oscillator anywhere in 10,390 lines. The metronome is a flashing dot. “Hear” buttons, progression “Play” buttons, the score playhead and the piano are all mute.

Fix: one lib/audio.ts singleton unlocked on first user gesture, with a lookahead scheduler (25 ms timer, 100 ms schedule-ahead window) for the metronome and a sampled or Karplus–Strong pluck for note playback. Roughly 250 lines unlocks eight features at once. This is the highest-leverage change in the report.

03

The tuner is a simulation that reports false confidence

TunerPage.tsx:50 drives the needle from Math.sin(t). It displays “♦ IN TUNE” and a frequency in Hz without ever opening the microphone. A user who trusts it will detune their guitar.

Fix: getUserMedia → AnalyserNode → autocorrelation or YIN pitch detection (~120 lines), a median filter over the last five frames for needle stability, and an explicit “no signal” state. Until then, label the page “Demo” — shipping a fake tuner is a trust problem, not a feature gap.

04

No persistence layer at all

Streak, XP, heatmap, routine checkboxes, settings, tab edits, imported songs — all component state. Refresh and it is gone. The heatmap and contribution graph are worse than reset: they are Math.random(), so they show a different past each load.

Fix: a PracticeStore context over localStorage with a versioned schema — sessions, XP ledger, exercise PBs, settings, custom routines. Ship that first; swap the same interface to a real backend later without touching components.

05

Four TypeScript errors — the build does not typecheck

vite build succeeds because Vite does not typecheck. tsc --noEmit reports: an unknown module in imports/index.tsx; invalid frets/startFret props in Library.tsx:273; a nullable PlayerType in TabStudio.tsx:295; and an unsupported onDark prop on LevelBadge at TabStudio.tsx:651.

Fix: add "typecheck": "tsc --noEmit" to scripts and make it a gate. Two of these four are silently broken UI, which is exactly what typechecking is for.

06

Roughly 40 finished components are built and never imported

CommandPalette, ToastStack/useToasts, DropdownMenu, ContextMenu, Switch, SliderField, TapTempo, DrillCard, SongCard, ScaleCard, TempoLadder, StepStrip, GoalBar, FinishLineCard, EmptyState, Tabs, KeyPicker, an entire second Tuner — all shipped in the 554 kB bundle, all unrendered.

Fix: this is an opportunity, not just waste. CommandPalette and ToastStack are the two things most missing from the UX (see the UI audit) and both are already written. Wire those two, keep the drill/song cards for the library rebuild, delete the rest.

07

src/imports/ is 58,238 dead lines

Three near-identical 17,000-line gallery HTML files, a PNG screenshot, a duplicate CSS design system, and an index.tsx that imports a module that does not exist. Nothing in src/ references any of it.

Fix: delete the directory, or move it out of src/ to design/ so it stops confusing tooling and search.

08

Duplicated, drifting data

Songs are defined twice (Tab Studio: 9, Library: 9 — overlapping but not identical). Scales are defined twice (Library: 8 hand-typed, Theory: 12 generated). The sidebar advertises “Chords 48” while the library holds 24, and “Songs 9”, “Scales 14” against different real counts.

Fix: one src/data/ directory as the single source — chords.ts, scales.ts, songs.ts, drills.ts — and derive every count in the UI from .length.

09

Contribution-graph range toggle only half works

PracticeGraph.tsx:42 captures data in a useState initializer, so the 13/26/52-week switch redraws the grid from the original 52-week array while “Total practice”, “Current streak” and “Avg/session” never change.

Fix: derive the visible window with useMemo from a stored session log rather than caching generated data.

10

Dead state and inert primary actions

Profile.tsx declares goals/setGoals and editingGoal then renders the GOALS constant instead. Across the app roughly 18 buttons have no handler, including “Start today’s session”, “Quick train”, the sidebar settings gear, every Explore row, “Print”, “Practice”, “+ Add goal”, “Save for later” and all six progression “Play” buttons.

Fix: a lint rule banning <button> without onClick, plus a triage pass — wire it, or remove it until it exists. An inert button reads as a bug to users, not as “coming soon”.

UI/UX audit against modern SaaS

Where FretLab already competes, and the eight gaps a Linear/Notion/Duolingo-tier user would notice in the first two minutes.

What already competes

  • The token system is real. A coherent cream/violet palette, an oklch key-hue axis, five shadow tiers, named motion easings. Most indie apps never get this far.
  • Lexend + JetBrains Mono is a strong, non-obvious pairing — Lexend is literally designed for reading proficiency, which is defensible for a learning tool.
  • Data density is right. Dark instrument surfaces against light chrome gives the fretboard, score and tuner real presence.
  • The score view and chord diagrams are portfolio-grade drawing work.

The eight gaps

1 · No mobile layout

  • Zero @media queries in the entire codebase.
  • Fixed 224px 1fr shell; Tab Studio adds a fixed 286px column.
  • Below ~900 px the app is unusable — and a guitarist practices with a phone on a music stand.
  • This is the single biggest UX gap, ahead of everything below.

2 · No feedback layer

  • No toasts, no confirmations, no optimistic states. ToastStack is written and unused.
  • No loading skeletons; the only “loading” is a fake 800 ms delay.
  • No empty states — EmptyState exists, unused.
  • No error boundary: one bad song object white-screens the app.

3 · Everything is inline styles

  • ~8,000 lines of style={{…}} with no hover/focus/active states, because inline CSS cannot express them.
  • Hover is hand-patched with onMouseEnter in a handful of places and absent everywhere else.
  • Tailwind v4 is installed and essentially unused.
  • Consequence: the app feels flat and unresponsive to the cursor — the clearest “not a real SaaS” tell.

4 · No keyboard layer

  • No shortcuts at all — not even Space to start the metronome.
  • CommandPalette is built and unmounted; ⌘K is table stakes now.
  • Card “buttons” are <div onClick> — not tabbable, not Enter-activatable.
  • Practice tools especially need hands-free control: you are holding a guitar.

5 · Dark mode is a lie

  • The theme switcher stores a value and changes nothing.
  • No dark token block exists — the palette is light-only.
  • Practicing at night on a bright cream canvas is a real complaint waiting to happen.

6 · Static chrome

  • The top-bar key badge always says “C major” and is not a control.
  • “Quick train →” does nothing; the settings gear does nothing.
  • Sidebar “Explore” rows are hover-styled but unclickable, with counts that don’t match reality.
  • The avatar is hardcoded to “Jamie Davis · Intermediate”.

7 · No onboarding or progressive disclosure

  • A first-time user lands on a dashboard claiming a 14-day streak they never earned.
  • No skill assessment, no goal-setting, no “what do you want to learn” path.
  • Duolingo’s entire retention model starts here; yours starts at a fabricated dashboard.

8 · Accessibility is partial

  • The unused controls.tsx has excellent ARIA. The shipped pages mostly don’t.
  • Clickable divs throughout the drill, exercise, lesson and song lists.
  • Color-only state on fretboard tones and heat cells.
  • No prefers-reduced-motion handling despite constant animation.

If you fix one thing in this section: move off inline styles onto Tailwind (already installed) or CSS modules, so that hover, focus, active and dark variants become expressible. Gaps 3, 5 and 8 all collapse into that one migration, and the “modern SaaS feel” you’re chasing lives almost entirely in those states.

Completing the gamification concept

You have the stem: an XP curve, eleven rank titles, a league with promotion zones, four weekly challenges, eight achievements. What’s missing is the loop that connects playing a guitar to any of it.

Today PLAYER.xp = 8450 is a constant. Nothing awards XP. Nothing increments a challenge. No achievement is ever unlocked. The economy has a currency and no mint. Here is the full concept.

1 · The XP mint — where points come from

EventXPDesign intent

Drill completed at target BPM40 XPRewards finishing, not just starting.

2 · Streak mechanics that survive real life

  • Minimum viable day: 5 minutes or one completed drill counts. Make the floor low enough that streaks rarely die by accident.
  • Streak freeze: earn one per 7-day streak, hold a maximum of two, auto-spend on a missed day. This is the single highest-impact retention mechanic in Duolingo and it’s cheap to build.
  • Streak repair: within 48 hours, restore a broken streak by completing a double session. Converts churn moments into engagement.
  • Rest days: let users designate one weekly rest day that never breaks a streak. Guitarists get sore hands; punishing that is bad pedagogy.
  • Milestone rewards at 7/14/30/100/365 days — badge, and a cosmetic fretboard inlay skin.

3 · Turn the league into a real system

  • Ten tiers, not one. Nylon → Bronze → Copper → Amethyst (you have this one) → Sapphire → Emerald → Ruby → Obsidian → Platinum → Legend.
  • Cohorts of 30, assigned on first qualifying session of the week, top 7 promote, bottom 5 relegate.
  • Weekly reset Sunday 23:59 local. The “Ends in 3d” badge is already rendered — make it a live countdown.
  • Bot cohorts at launch. With no user base, seed leagues with plausible bot schedules. This is standard practice and it’s the only way leagues work pre-scale.
  • Rank-change animation on Monday — the payoff moment the current static list has no room for.

4 · Achievements as a real taxonomy

Consistency

  • Streaks at 7 / 14 / 30 / 100 / 365 days
  • Practice before 7 am ×10 — Dawn Patrol
  • Practice after 11 pm ×10 — Night Shift
  • Every day of one calendar month

Technique

  • Any drill at 180 BPM — Speed Demon
  • All 5 pentatonic boxes at 120 BPM — Box Set
  • F barre clean at 80 BPM — Barre Exam
  • Sweep arpeggio clean at 140 — Sweeper

Knowledge

  • All 10 lessons complete — Theory Scholar
  • Perfect score on 5 quizzes — Straight A
  • Name all 12 keys’ signatures — Circle Master
  • Identify 20 intervals by ear — Golden Ear

Repertoire

  • First song end to end — Encore
  • 10 songs mastered — Setlist
  • A song in each of 5 genres — Session Cat
  • Write and export an original tab — Composer

Exploration

  • Play in all 12 keys — Twelve Tones
  • Use all 5 alternate tunings — Retuned
  • Every mode of the major scale — Modal Nomad

Hidden / delight

  • Tune all 6 strings within 2¢ in one pass — Perfect Pitch
  • Practice on a public holiday — No Days Off
  • Play Smoke on the Water on day one — Obligatory

5 · The missing middle: mastery per item

Right now progress is one global number. Real practice apps track mastery per drill, per chord, per scale shape. Give every library item a five-state ladder — New → Learning → Familiar → Solid → Mastered — promoted by clean runs at increasing tempo and demoted by decay over time. That single addition gives you:

  • A spaced-repetition queue — “7 items are due for review” is the strongest possible reason to open the app.
  • A real “Today’s routine” generated from weakest items rather than a fixed list.
  • Meaningful heatmap colors (mastery gained, not minutes idled).
  • Honest achievement criteria, since “mastered” finally has a definition.

  • Licensing note — see below

Licensing, before you scale this. Tab transcriptions of copyrighted songs are derivative works. The NMPA’s 2010s enforcement closed several large tab sites; Ultimate Guitar and Songsterr operate under publisher licences.

Safe paths: public-domain and traditional material (House of the Rising Sun already qualifies), original exercises and études you author, user-uploaded private tabs the user does not publish, and chord-only progressions (chord sequences are not copyrightable in the same way full transcriptions are). Build the ladder above from those three sources first, and treat licensed commercial tabs as a later business-development step rather than a content task.

Ranked by leverage against what already exists, not by novelty.

Tier 1 · Unlocks everything else

  • Audio engine — metronome with accents and subdivisions, count-in, note playback for piano/fretboard/chords, progression playback. Eight dead buttons become live.
  • Real pitch detection — the tuner, plus bend trainer, intonation checker, and “did you play it right?” drill scoring.
  • Persistence + session logging — makes every stat in the app true.
  • Practice session player — the thing “Start today’s session” should open: a full-screen, step-by-step runner with timer, metronome, tab, and auto-advance.

Tier 2 · Core differentiators

  • Tempo ladder / speed trainer — auto-increment BPM by 2–5 after each clean pass. TempoLadder is already written and unused.
  • Loop & slow-down player — A/B loop with time-stretch over the YouTube embed. The single most-used feature in every competing app.
  • Spaced-repetition review queue — driven by the mastery ladder.
  • Routine builder — drag drills into a template, save, schedule, share.
  • Real AI — replace the keyword table with an API call, and wire the context field so tapping a fret asks about that note in this scale.

Tier 3 · Depth

  • Backing tracks per key, tempo and style, generated from the progression data you already have.
  • Recording — capture a take, attach it to the session, compare week over week. Your Account panel already promises storage for it.
  • Ear training module — intervals, chord qualities, progressions; the theory content already supports it.
  • Fretboard note trainer — timed, gamified, feeds the knowledge achievements.
  • MIDI input — “Connected apps” already lists a MIDI controller.
  • Capo & transpose across every tab and chord chart.
  • Left-handed mode and alternate/extended-range tunings throughout.

Tier 4 · Product surface

  • Auth and cloud sync — your own APP-TEMPLATE-CONTRACT.md specifies sign-up, sessions, password reset and protected routes. None exist.
  • Onboarding — skill assessment, goal selection, generated first routine.
  • Teacher/student mode — assign routines, review student logs. This is where the revenue is.
  • Shareable progress cards — a rendered “14-day streak” image is free distribution.
  • PWA + offline — practice happens where wifi doesn’t.
  • Export — PDF chord sheets, MusicXML, Guitar Pro, plain ASCII from the tab editor.

Suggested sequence

Ordered so each phase makes the next one cheaper. Phase 0 exists because shipping a fake tuner and wrong chord shapes costs more trust than any feature buys.

Phase 0

Stop teaching wrong information

Fix the 8 chord voicings and add the derive-and-assert test. Fix the 4 type errors and gate the build on tsc. Label the tuner and AI panel as demos until they are real. Delete src/imports/. Remove or wire the 18 inert buttons.

Phase 1

Make it real

Audio engine. Persistence store with session logging. Replace every hardcoded stat and every Math.random() dataset with derived values. Ship the practice session player behind “Start today’s session”.

Phase 2

Make it feel like software

Migrate inline styles to Tailwind. Add hover/focus/active states, dark mode, mobile breakpoints. Mount CommandPalette and ToastStack. Add an error boundary and empty states. Fix keyboard access on card lists.

Phase 3

Close the gamification loop

XP mint, mastery ladder per item, streak freezes, real leagues with bot cohorts, the full achievement taxonomy, and the spaced-repetition review queue that ties it all to daily return.

Phase 4

Scale the library

Move all content into src/data/, generate chords from formulas, unify scales onto the Theory Studio engine, build the song ladder from public-domain and original material, and expand drills to 30 with real tabPattern data.

Phase 5

Become a product

Auth and cloud sync, onboarding, real AI with fretboard context, loop/slow-down player, recording, and the teacher/student tier.

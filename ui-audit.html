The headline

A complete, documented design system already exists in this repo, and the shipped app does not use it.

src/imports/ is not the dead weight the first audit called it. It contains a token file with a full dark-theme block, a stylesheet of 441 component classes carrying every interaction state, a written control specification, and a component inventory mapping each screen to its parts.

The shipped app uses none of it, rendering 1,078 inline style={{…}} objects instead. Almost every problem in this report is downstream of that one fact.

1 · Design system conformance

Where the shipped token layer diverges from the system it was copied from, and how loosely the app holds its own scales.

1.2  Scale discipline is weak

The token file defines tight scales. The app improvises around them.

The 41 font sizes include 0.62, 0.63, 0.64, 0.65, 0.66, 0.67, 0.68 and 0.7rem — eight steps inside a 0.08rem band, below the threshold anyone can perceive as intentional hierarchy. It reads as drift, and it is the main reason the interface feels slightly unresolved at small sizes despite the strong palette.

--fl-motion-fast and --fl-motion-base are defined and used zero times; 15 hand-picked durations from 60ms to 700ms appear instead, so related interactions animate at unrelated speeds.

1.3  Color and z-index bypass the system

  • 183 raw hex literals across 35 distinct values in pages and components.
  • Several are exact duplicates of existing tokens: #6152d9 is --fl-accent (10 uses), #b7abf7 is --fl-root (21 uses), #3fa87a is --fl-live (17 uses), #8b7cec is --fl-third (6 uses).
  • Twelve z-index values with no scale — 0, 1, 20, 20, 99, 100, 200, 9999, 9999, 10000, 99999. controls.tsx alone escalates 9999 → 10000 → 99999, while the two defined z tokens go unused.

2 · Screen by screen

Captured at 1440×1150 against the running app.

2.1  Practice Studio  /

Works: the mono stat row at 1.8rem is confident. The routine checklist, week strip and level card form a coherent right rail.

  1. The hero ends on a hard horizontal edge. No gradient, shadow or overlap resolves the dark band against the cream canvas, so the page reads as two documents stacked.
  2. The practice-history card is mostly empty. The card runs the full ~710px content width; the heatmap inside occupies ~220px, flushed left. Either the cells scale up or the card shrinks to its content.
  3. Two competing primary buttons are visible at once — "Quick train" in the top bar and "Start today's session" in the hero, both solid accent. The control spec is explicit: "primary is reserved for the next or highest-confidence action." Only one can be.
  4. Warm-up card rows don't share a baseline. Cards size to content, so a one-line description lifts that card's BPM chip row above its neighbours'.
  5. The four hero stats use four unrelated colors with no semantic meaning. Color spent as decoration leaves nothing for real state.
  6. "2 of 5 tasks done" sits at 1.94:1 on the dark hero. Effectively invisible.
  7. The sidebar's 01–06 numerals imply a sequence that does not exist. Navigation is not a process; numbering it is structure used as ornament.

2.2  Library  /library

  1. Chord diagrams lose the nut on any open chord whose lowest fretted note is above fret 1. ChordDiagram computes baseFret = min(positives) and draws the nut only when baseFret === 1. So G, Em, D, A, Bm, Asus2, Dsus4 and Caug — 8 of the 16 shown — render a misleading position marker and no nut, as if they were movable shapes high on the neck. This is separate from the seven wrong fret arrays in the code audit.
  2. An orphaned card sits alone on the last row. 16 chords in a 5-column grid leaves one. Pick a column count the collection fills.
  3. Roughly 700px of vertical dead space under the detail panel, which is 320×110 in a column running the full page height.
  4. Three different selection treatments on one screen — folder tabs, filter pills and card selection. The control spec distinguishes these deliberately, but on screen they read as three unrelated languages.
  5. Finger numbers inside the dots are near-illegible — dark text at ~7px on saturated fills.
  6. Within-card alignment is inconsistent: chord name left-aligned, formula centered.

2.3  Tab Studio  /tab

  1. Chrome overwhelms content. Global nav 224px + song list 286px + right rail 196px = 706px of fixed furniture, leaving the tab ~650px, less than half the window.
  2. The tab is the smallest text on the page — 0.78rem mono against 0.8–0.92rem UI text. It is the reason the page exists and should be the most legible thing on it.
  3. The same cover photo appears twice, as hero background and again in the right rail ~400px away.
  4. The hero image is over-darkened past the point of reading as an image, while still costing a full-width fetch.
  5. "Print" is a light button floating on unpredictable photography. Its contrast depends on whichever cover art loads.
  6. The import placeholder is clipped mid-word — two 11px platform icons sit at left: 8 against a paddingLeft: 28, leaving ~3px of clearance.
  7. ~350px of dead canvas below the notation legend — which documents glyphs the parser silently discards.

2.4  Theory Studio  /theory

Works: clear ring hierarchy, readable at every radius, correct relative-minor placement. The degree chips and neighbouring-key row are both well judged.

  1. The circle's palette belongs to a different product. Wedge fills run a full 360° hue rotation while the rest of the app is violet-on-cream. The intent — key identity as hue — is sound and documented, but nothing else in the app carries the key hue, so it reads as an imported rainbow rather than a system.
  2. ~440px of dead space below the circle, which sits in a 1fr column sized for a much taller sibling.
  3. Six identical quiet "Play" buttons stack in a column, all inert. Repetition at that density turns a control into visual noise.
  4. Neighbouring keys use the app's disabled surface for the two side cards, so they read as unavailable rather than adjacent.
  5. Hero heights are inconsistent across routes — Practice ~440px, Library ~250px, Theory ~250px, Tab ~200px, Profile none. Navigating makes the layout jump.

2.5  Tuner  /tuner

This is the most visually broken screen in the app, and only looking at it reveals it. Reading the source finds the fake pitch detection; it does not find the mis-rendered dial.

  1. The gauge geometry is wrong. The needle is drawn from centre pointing up-left while the scale arc renders as a partial ring on the right side only. arcPath applies toRad(d - 90) to an argument already offset by +90, double-rotating the arc out of the needle's frame.
  2. "0¢" is labelled twice, at two different positions on the ring.
  3. Three text elements overlap — the "455 Hz" readout, the demo-mode pill, and a tick label all collide.
  4. The level meter runs underneath the demo-mode pill.
  5. The note letter and octave are mis-positioned — "C" sits left of centre with "4" floating away from it, and the needle passes through the glyph.
  6. Two controls do the same job, simultaneously visible — the string chip row and the "String reference" list are both string selectors.
  7. ~60% of the page is empty, all of it lower-left.
  8. It is the only fully dark route. The control spec states the direction is light-first, with cinematic contrast contained inside instrument surfaces. Here the instrument surface has eaten the page.

One thing this screen does right that the earlier read missed: it already discloses demo mode in that pill. The disclosure exists. It is just illegible because three elements are stacked on top of it.

2.6  Profile  /profile

The page contradicts itself in two places visible at once. The hero reads 14d streak · 147h total hours · 312 exercises. The Practice Activity card immediately below reads 18d current streak · 261h 16m total practice · 266 total sessions.

The first set is hardcoded JSX; the second is Math.random() at mount. A user sees two different truths about their own practice without scrolling.

  1. A hard-edged rectangle artifact sits behind the hero stats. The decorative bloom is a 400px circle at opacity: 0.08 positioned outside its container's bounds inside overflow: hidden, so it clips to a visible rectangle instead of reading as a soft glow.
  2. Weekly Challenge cards have unequal heights. The completed card carries a "Complete" line where others carry a count, so row 2 is taller than row 1.
  3. The level progress bar is effectively invisible — a thin track on dark with a very small fill.
  4. Promotion and relegation dividers are nearly imperceptible — 1px dashed at low alpha.
  5. Emoji stand in for iconography alongside an otherwise custom SVG icon set. They render inconsistently across platforms and are the one visual choice here that reads as template rather than design.
  6. Accent is applied arbitrarily in the stat row: of four figures, only one is colored.

3 · Responsive

Zero @media queries in 10,390 lines, against 18 in the design system. This is not degradation, it is absence.

At 390px, the width of the phone most likely to be on a music stand:

  • The sidebar is a fixed 224px — 57% of the viewport — and does not collapse.
  • The greeting renders as "Good", clipped mid-phrase.
  • "Practice history" and "Warmups & Fin…" are both cut off.
  • The primary call to action wraps to three lines inside its pill.
  • The heatmap is clipped at the viewport edge, and the page scrolls horizontally.

Tab Studio at 390px is functionally unreachable. Its layout is a 224px sidebar plus a 286px song list — 510px of fixed columns in a 390px viewport. The tab, the entire purpose of the route, begins at x=510 and is never visible. No scroll affordance reveals it.

The app template contract already fixes the answer: sm 640 / md 768 / lg 1024 / xl 1280, mobile-first shells, sidebar collapsing to a bottom bar under md. None of it is implemented.

The two that matter most:

  • --fl-ink-4 is the app's metadata color — fret numbers, counts, durations, timestamps, the heatmap legend, "16 weeks · 312 sessions". It fails on every surface it is used on, by a wide margin. It needs to darken to roughly #6f6a7b to clear 4.5:1 on --fl-surface.
  • --fl-live at 2.91:1 is used both as a status dot and as text (17 hardcoded occurrences). As a dot it is acceptable; as text it is not. --fl-success at 4.54:1 already exists and should carry the text role.

Semantics and keyboard

The design system's accessibility checklist specifies keyboard-addressable fretboard markers, roving focus in pill groups, arrow-key navigation in the heatmap, live announcements for tuner and stepper readouts, and selection encoded by shape and boundary in addition to color. The shipped app implements essentially none of it:

  • Clickable <div>s carry the primary interaction on warm-up cards, exercise rows, lesson rows and song cards. Not focusable, not Enter-activatable, not announced as controls.
  • One focus style for the entire app, against the system's 8 component-specific treatments.
  • No aria-expanded on any expand/collapse card, of which there are four kinds.
  • Selection is color-only in several places, against the spec's explicit "never color alone".
  • No prefers-reduced-motion handling, against 6 rules in the system, while the app animates a playhead, a needle, a metronome pulse, progress rings, streaming text and a slide-in panel.

Touch targets

Several controls fall below the 44px minimum: heatmap cells are 11px, the sidebar settings control 28px, the AI panel close button 28px, quick-tempo chips ~24px tall. The control system specifies 32 / 40 / 48px heights and none of these conform.

5 · Interaction, motion and architecture

Interaction and motion

  1. Hover exists in six places and is implemented in JavaScript. Handlers mutate style.background directly. Everywhere else there is no hover state, because an inline style object cannot express one. This is the clearest reason the interface feels inert under the cursor.
  2. No :active state anywhere, against the spec's 0.97 scale on press.
  3. No disabled styling, despite 14 :disabled rules in the system and the attribute being used in the app.
  4. No loading or pending states. The only "loading" is an artificial 800ms timeout in the song importer.
  5. The metronome pulse runs on wall-clock setInterval, so the visual beat drifts away from any audible reference within a minute.

Information architecture

  1. The top bar is largely non-functional furniture. The key badge permanently reads "C major" with a dropdown chevron but is not a control. "Quick train" has no handler. The centre pill duplicates the breadcrumb already at the left, so the page name appears twice in one 52px band.
  2. Sidebar "Explore" rows are hover-styled but unclickable, and their counts match nothing the app contains.
  3. Drills live only on the dashboard, though the product's own feature list places them in the Library — which has three tabs where the spec describes four.
  4. Library and Tab Studio both list songs, from two separate hardcoded arrays, with no navigation between them. Library's "View tab" does not go to the tab.

Content and copy

  • Em dashes appear throughout shipped copy — against an explicit prohibition in the contract's copy rules.
  • All-caps labels are used widely via textTransform: uppercase. Some are decorative typography and defensible; the ones acting as field labels are not.
  • Copy asserts things that are not true: "Your 14-day streak is alive", "Music theory assistant", "IN TUNE" with the microphone closed, "2.4 GB / 10 GB".
  • Button verbs are mostly good, but confirmations don't reuse them because there are no confirmations.
  • "Voicing coming soon" is the only place the app admits an absence, and it does it well.

Backlog changes this audit implies

  • P0-07 reframed. It currently treats src/imports/ as dead weight to move aside. It should instead extract tokens.css, fretlab-ui.css, CONTROL-SYSTEM.md and README.md to packages/design-system/ as the system of record, discarding only the three prebuilt gallery HTML files and the screenshot. The "move rather than delete" instinct was right; the framing was wrong.
  • P6-03 is much cheaper than scoped. It assumes the dark palette must be authored. It exists and needs porting plus the theme-attribute wiring.
  • New task needed: fix ChordDiagram nut rendering. Derive "is open position" from the presence of open strings, not from the minimum fretted value. Slot it in Phase 0 beside P0-01.

What's genuinely good

Worth protecting through the migration.

  • The circle of fifths. Correct, legible, well-proportioned, and the hue-per-key idea is a real system rather than decoration. It just needs the rest of the app to carry it.
  • The contribution graph. Dense, readable, correct cell sizing, good legend.
  • The score view's piano roll. The strongest drawing work in the product.
  • Lexend + JetBrains Mono. A defensible, non-obvious pairing for a learning tool. Restore the Atkinson Hyperlegible fallback.
  • The cream and violet palette with dark instrument surfaces. A genuine identity, and the right instinct: chrome is paper, instruments are lit. The tuner is the only place that inverts it, and that looks like an accident rather than a decision.
  • The AI panel's provenance line. "Verify before use in performance or teaching" is honest, specific and correctly placed. Keep the pattern when the panel becomes real.
